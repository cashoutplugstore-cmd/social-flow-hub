# Social Flow Hub

أريد منك بناء منصة ويب احترافية كاملة باسم [اسم المنصة] لبيع خدمات السوشيال ميديا الرقمية، مع تصميم حديث جداً Mobile First وResponsive وRTL، واللغة العربية هي الافتراضية مع إمكانية إضافة الإنجليزية لاحقاً.



1. فكرة المنصة



المنصة عبارة عن متجر رقمي لشراء الخدمات المتعلقة بمنصات التواصل الاجتماعي، مثل:



- شحن TikTok Coins / خدمات TikTok الرسمية حسب ما تسمح به المنصة.

- خدمات الترويج والإعلانات للمحتوى.

- خدمات زيادة الوصول والمشاهدات بطريقة حقيقية ومشروعة.

- خدمات YouTube.

- خدمات Instagram.

- خدمات TikTok.

- خدمات Telegram.

- خدمات Facebook.

- خدمات X.

- خدمات Discord.

- خدمات تصميم المحتوى.

- خدمات التسويق الرقمي.





2. الصفحة الرئيسية



صمم Landing Page قوية جداً تحتوي على:



- Navbar احترافي.

- Logo باسم المنصة.

- تسجيل الدخول / إنشاء حساب.

- زر "ابدأ الآن".

- Hero Section جذاب:

  "كل خدمات السوشيال ميديا في مكان واحد"

- عرض المنصات المدعومة.

- الخدمات الأكثر طلباً.

- لماذا تختارنا؟

- طريقة العمل في 3 خطوات.

- أحدث الطلبات/إحصائيات عامة بدون كشف بيانات العملاء.

- FAQ.

- Footer احترافي.



3. متجر الخدمات



أنشئ صفحة Services تحتوي على Categories:



TikTok

YouTube

Instagram

Telegram

Facebook

X

Discord

Digital Marketing

Design



كل خدمة تظهر كـ Card تحتوي:



- اسم الخدمة.

- المنصة.

- وصف مختصر.

- السعر.

- مدة التنفيذ المتوقعة.

- حالة الخدمة.

- زر "اطلب الآن".



أضف البحث والفلاتر والترتيب حسب السعر والشعبية والمنصة.



4. صفحة تفاصيل الخدمة



عند فتح الخدمة تظهر:



- اسم الخدمة.

- وصف كامل.

- السعر.

- الكمية.

- الحد الأدنى والأقصى.

- وقت التنفيذ المتوقع.

- تعليمات الطلب.

- رابط/بيانات الحساب المطلوبة فقط عند الحاجة.

- ملاحظات مهمة.

- زر "إضافة للسلة".

- زر "شراء الآن".



لا تطلب كلمات مرور حسابات المستخدمين أبداً.

- الطلبات المكتملة.



Orders

6. نظام الرصيد والمحفظة



أنشئ Wallet System:



- الرصيد الحالي.

- إضافة رصيد.

- سجل المعاملات.

- المبالغ المستخدمة.

- المبالغ المستردة.



أضف إمكانية الدفع الإلكتروني بطريقة آمنة، ويفضل Stripe عندما يكون متاحاً.



لا تخزن بيانات البطاقات داخل قاعدة البيانات.



7. نظام الطلب



عند شراء خدمة:



1. اختيار الخدمة.

2. تحديد الكمية.

3. إدخال البيانات المطلوبة.

4. مراجعة الطلب.

5. الدفع.

6. إنشاء Order.

7. إظهار رقم الطلب.

8. متابعة حالة الطلب من Dashboard.



بعد إنشاء الطلب تظهر صفحة Success فيها:



"تم إنشاء طلبك بنجاح"



مع Order ID.



8. نظام التذاكر والدعم



أضف Support Center:



- إنشاء Ticket.

- عنوان المشكلة.

- القسم.

- الرسائل.

- حالة التذكرة.

- الرد من الإدارة.



أضف Live Chat UI قابل للتطوير لاحقاً.



9. لوحة الإدارة Admin Dashboard



أنشئ لوحة إدارة احترافية منفصلة.



Dashboard تعرض:



- إجمالي المستخدمين.

- المستخدمين الجدد.

- إجمالي الطلبات.

- الطلبات اليوم.

- الإيرادات.

- الطلبات المعلقة.

- الطلبات المكتملة.

- التذاكر المفتوحة.



إدارة المستخدمين



Admin يستطيع:



- مشاهدة المستخدمين.

- البحث.

- تعطيل/تفعيل الحساب.

- مشاهدة الطلبات.

- مشاهدة الرصيد.

- تعديل الرصيد فقط مع تسجيل العملية في Audit Log.



إدارة الخدمات



Admin يستطيع:



- إنشاء خدمة.

- تعديل خدمة.

- حذف/إخفاء خدمة.

- تحديد السعر.

- تحديد الحد الأدنى والأقصى.

- تحديد المنصة.

- تحديد مدة التنفيذ.

- تفعيل/تعطيل الخدمة.



إدارة الطلبات



Admin يستطيع:



- مشاهدة جميع الطلبات.

- فلترة الطلبات.

- تغيير الحالة.

- إضافة ملاحظات داخلية.

- معالجة Refund حسب النظام.



إدارة التذاكر



Admin يستطيع:



- مشاهدة Tickets.

- الرد.

- تغيير الحالة.

- تعيين التذكرة لمشرف.



10. نظام API للخدمات



صمم Architecture يسمح مستقبلاً بربط مزودي خدمات خارجيين عبر API.



أنشئ abstraction layer مثل:



Service Provider

Provider API

Provider Order

Provider Status



بحيث لا يكون الكود مربوطاً بمزود واحد.



لا تنفذ أي API لمشاهدات أو تفاعل وهمي أو خدمات مخالفة لسياسات المنصات.



11. قاعدة البيانات



استخدم Supabase/PostgreSQL.



أنشئ جداول منظمة مثل:



users

profiles

services

service_categories

orders

order_items

wallets

wallet_transactions

payments

tickets

ticket_messages

notifications

audit_logs

providers

provider_orders



استخدم UUIDs.



فعّل Row Level Security بشكل صحيح.



المستخدم يستطيع الوصول فقط إلى بياناته.



Admin فقط يستطيع الوصول إلى بيانات الإدارة.



12. Notifications



أضف نظام Notifications:



- إنشاء طلب.

- نجاح الدفع.

- تغيير حالة الطلب.

- اكتمال الطلب.

- Refund.

- رد على Ticket.



13. التصميم



أريد التصميم Premium وليس Template عادي.



Style:



- Modern SaaS.

- Dark/Light mode.

- Glassmorphism بشكل خفيف.

- Cards نظيفة.

- Animations خفيفة.

- Icons احترافية.

- RTL ممتاز.

- Mobile First.

- Sidebar Dashboard.

- Bottom navigation للموبايل عند الحاجة.



استخدم Tailwind + shadcn/ui + Lucide icons.

Home → Service → Order → Payment → Order Tracking



لا تجعل المستخدم يضيع داخل الموقع.



أضف Loading States وEmpty States وError States وSuccess States.



18. SEO

- Open Graph.

- Sitemap.

19. مهم جداً



لا تضع أي أسرار أو API Keys داخل Frontend.



إذا كانت هناك Integration تحتاج API Key، اجعلها Server-side فقط.



اكتب الكود بطريقة Production-ready وقابلة للتوسع.



قبل إنهاء العمل:



- اختبر التسجيل والدخول.

- اختبر Wallet.

- اختبر صلاحيات المستخدم.

- اختبر صلاحيات Admin.

- اختبر RLS.

- اختبر Responsive Design.

- أصلح أي أخطاء TypeScript أو Console.
